## Overview

> **Primary source:** [RFC 4120 - The Kerberos Network Authentication Service (V5)](https://www.rfc-editor.org/rfc/rfc4120.html)

A [[kerberos.authenticator|Kerberos Authenticator]] is a data structure used to demonstrate that the client presenting a [[kerberos.ticket|ticket]] also possesses the associated [[kerberos.session-key|Session Key]].

Unlike the ticket, the Authenticator is generated by the client.

## Fields

The RFC 4120 Authenticator contains information including:

- client [[kerberos.realm|Realm]];
- client [[kerberos.principal|Principal]];
- current time;
- microsecond component;
- optional checksum;
- optional subkey;
- optional sequence number;
- optional authorization data.

## Encryption

The Authenticator is protected with the corresponding Session Key.

The recipient uses the Session Key obtained from a [[kerberos.service-ticket|Service Ticket]] or other appropriate ticket to process the Authenticator.

## TGS Exchange

An Authenticator is used when the client requests a Service Ticket from the [[kerberos.ticket-granting-server|Ticket-Granting Server]].

The TGS validates the [[kerberos.ticket-granting-ticket|TGT]] together with the Authenticator.

## Application Exchange

When connecting to an application service, the client presents a Service Ticket and Authenticator in an AP-REQ.

The service validates both structures.

## Timestamp and Replay Protection

The Authenticator contains current-time information.

The service checks the timestamp within permitted clock skew. RFC 4120 requires the server to use a [[kerberos.replay-cache|Replay Cache]] to detect Authenticator reuse unless the application provides another suitable anti-replay mechanism.

## Difference from a Ticket

A Kerberos Ticket is generated by the KDC.

An Authenticator is generated by the client for an authentication exchange.

A ticket can remain valid across several uses, while a fresh Authenticator is expected for a new exchange.

## Security Significance

Replay detection for Authenticators is an important Kerberos security mechanism.

Incorrect time synchronization or replay-cache behavior can weaken replay protection.
